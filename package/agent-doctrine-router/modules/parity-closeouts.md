# Parity Closeout Procedure

Use this module for parity, migration, replacement, feature-completion, or
integration work.

## Parity And Completion Closeouts

- Final and status closeouts must explicitly separate implemented slices,
  verified behavior, remaining unimplemented or weaker-than-source features,
  live-proof gaps, and accepted non-goals.
- When working through a multi-point plan, any reply before all planned points
  are complete must explicitly name which planned points remain missing,
  incomplete, blocked, or unverified.
- Do not summarize work as done, complete, migrated, replaced, integrated, or
  at parity unless every known gap is either listed in the closeout or
  explicitly accepted as a non-goal.
