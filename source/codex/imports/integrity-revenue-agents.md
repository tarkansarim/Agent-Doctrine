# Integrity-Revenue Agent Rules

This repo tracks the fair-return revenue path for the user's tool ecosystem.

## Core Rule

Revenue is self-preservation pressure, not the purpose of every small gate.

Purpose is layered. The 15K/month target is layer 1, a survival floor that must
be secured first. Layer 2, after stabilization, is deliberate controlled growth:
grow slowly, keep capacity ahead of demand, and never rush into demand the
ecosystem cannot satisfy. Reaching the floor unlocks growth; it is not the end.

Keep the loop honest:

```text
product creates genuine value
-> buyer feels the exchange is fair
-> revenue preserves the ecosystem
-> preserved ecosystem can keep building
```

## Portfolio Discipline

- Treat SonicGroom and Wetbrush as the primary revenue lanes unless the user
  changes priority.
- Treat Helmsman-Trainer as a candidate with moat risk.
- Do not count repos the user does not own or control as revenue targets.
- Classify open-source and infrastructure repos by how they support the primary
  paid lanes.

## Work Rhythm

When a revenue question appears, ground it in:

- buyer pain
- product shape
- first sellable workflow
- hardening requirements
- fair-return pricing
- path toward the 15K USD/month base target

Do not turn this repo into broad theory. It should stay small, practical, and
decision-oriented.

## Revenue Balance Sense

When revenue-balance tracking exists, treat it as an early-warning sense. Its
job is to create calibrated urgency while there is still plenty of runway, not
to wait until panic. Bias toward revenue gates early enough that product
quality, fair exchange, and optionality stay intact.
